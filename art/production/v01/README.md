# 표류도 그래픽 리소스 팩 v01

사용자가 승인한 [창고 컨셉](../../concepts/ch01_warehouse_mood_v01.png)을 기준으로 제작한다. 적당한 사용 흔적, 마른 표면, 부드러운 낮빛, 회녹색과 청회색 설비, 읽히는 그림자가 핵심이다. 검은방 3은 미스터리 분위기만 참고하며 모든 공간과 인물은 독립적으로 제작했다.

## 파일을 확인하는 방법

- [전체 이미지 미리보기](gallery.html): 종류·챕터·이름 검색, 원본 확대, 경로 복사.
- [전체 목록](ASSET_INDEX.md): 파일별 ID·용도·해상도·연결 검토 상태.
- [개발용 manifest](manifest.json): 실제 크기·용량·SHA-256·투명도·인물 및 상태 이미지 관계.
- [최종 생성 프롬프트](asset-plan-final.json): 이미지별 세부 구성과 조건. 제작 방식은 내장 image_gen이다.
- [최초 제작 계획](asset-plan.json): 최초 계획 보존용. 실제 제작 시 수정한 최종 프롬프트는 위 파일을 사용한다.
- [1챕터 연결 명세](ch01-render-contract.json): 시점·상태 이미지·핫스폿·아이템 레이어·근접 조작 영역.

`gallery.html`은 외부 서비스나 CDN에 의존하지 않는다. 브라우저에서 직접 열거나 `node scripts/serve-art.mjs`로 로컬 미리보기를 실행한다. 이 목록은 제작용이며 정답과 후반 인물·엔딩을 포함한다.

## 제작 범위

| 구분 | 계획한 범위 | 용도 |
| --- | --- | --- |
| 배경 | 41장 | CH01 11시점 + CH02~CH10 주요 공간 30장 |
| 상태 변화 | 7장 | 창고 개방·배수·게이트, 동굴 만조, 발전기 복구 |
| 아이템 | 26장 | CH01 데이터의 13개 + 후속 챕터 주요 도구 13개 |
| 인물 | 24장 | 6명 × 기본 초상 및 표정 3종 |
| 근접 퍼즐 | 10장 | CH01 손목·잠금함·환기구·배전함·달력·점검함·회로도·밸브·명판·키패드 |
| 이야기 화면 | 5장 | 타이틀 배경·섬 지도·엔딩 3종 |
| SVG | 개별 목록 참조 | UI 아이콘·패널·버튼·슬롯·정확한 단서 레이어 |

현재 생성 완료 수량은 `manifest.json`의 `counts`와 전체 목록에 기록된다. 최종 전달 전에 누락 파일과 투명 배경을 검사한다. `layout-review`는 CH02 이후 세부 퍼즐와 동선을 확정할 때 배치를 검토해야 하는 자산이다. 실제 PNG가 존재한다는 뜻과 시즌 전체 게임 구현이 끝났다는 뜻을 구분한다.

## 폴더와 이름 규칙

`backgrounds/ch01~ch10/`는 탐색 배경이다. `states/`는 전체 배경 교체용 상태 이미지다. `items/`는 투명 아이템이다. `characters/{인물}/`는 투명 초상과 표정이다. `puzzles/ch01/`는 확대 화면이다. `title/`, `map/`, `story/`는 타이틀·지도·엔딩이다. `ui/icons/`, `ui/components/`, `overlays/`는 벡터 자산이다.

모든 PNG는 `_v01.png`로 원본을 보존한다. 수정 시 `_v02`를 새로 만들고 manifest의 실제 사용 경로를 갱신한다. 배경 PNG를 Photoshop 레이어 파일처럼 취급하지 않는다. 이 팩은 단일 배경 원본과 별도 아이템·벡터 레이어, 전체 장면 상태 변형으로 구성한다.

## 크기와 합성

제안한 1440×1720 배경·1600×2400 초상은 목표 사양이다. 이미지 생성 도구가 반환한 실제 픽셀 크기를 manifest에 기록했고 원본을 업스케일하지 않았다. 같은 장면과 상태 이미지의 크기가 달라도 동일한 `contain` 콘텐츠 영역에 맞춘 뒤 0~1 좌표를 사용한다. 이미지 일부를 잘라내는 `cover`는 사용하지 않는다.

아이템과 초상은 진짜 알파 PNG다. `alpha.contentRect`는 투명 여백을 포함한 원본에서 실체가 차지하는 사각형이다. 슬롯마다 전체 PNG를 늘리는 대신 이 값으로 크기 차이를 보정할 수 있다. 알파를 유지해 내보내고 흰 배경으로 평탄화하지 않는다. 원본 외곽의 얇은 알파는 밝고 어두운 배경 양쪽에서 확인한다.

SVG 패널은 장식 표면이며 접근 가능한 HTML 버튼·텍스트를 대신하지 않는다. 선택된 황색 버튼 위의 글자와 아이콘은 짙은색을 사용한다. 장식 아이콘은 `aria-hidden`, 행동 버튼은 한국어 이름을 제공한다. 모든 입력은 최소 44 CSS px이며 작은 물체의 터치 영역은 빈 주변으로 확대한다.

## 퍼즐 글자와 장치

선반의 숫자 4·1·7, 날짜 12, 근무조 3, F1·F2, 밸브의 이름, 명판의 기호와 UV 숫자는 SVG/HTML로 표시한다. 생성 배경에 우연히 생긴 작은 표시는 정답으로 사용하지 않는다. 잠금 장치의 정확한 현재 값은 근접 화면의 별도 숫자 UI가 담당한다.

쪽지와 회로도는 같은 SVG 좌표계에서 상단·하단을 연결한다. 텍스트를 지나치게 작은 장면 위에만 두지 말고 수첩 또는 확대 화면에서 전체 내용을 읽게 한다. 명판의 기호 위치는 섞어 두고, 새김 순서가 해법을 전달한다. UV 숫자 레이어를 초기 상태에 노출하지 않는다.

근접 장치 이미지는 조작 화면용 도안이다. 장면의 작은 장치와 원근·세부 기계 구조가 완전히 같은 사진 확대본은 아니므로, 전환 시 전체 구도보다 장치 종류와 색상으로 연결한다. 기계 눈금을 실제 물리 회전으로 해석하지 말고 게임의 상태 값으로 표시한다.

## 인물 사용

도윤의 내면 독백은 얼굴 없이 표시하고, 방송은 스피커 아이콘을 사용한다. 태오 얼굴은 CH08 이전에 노출하지 않는다. 서희는 기록·회상 프레임과 ‘기억 조각’ 문구로 현재 인물과 구분한다. 표정 자산은 동일 인물 기본 초상을 편집해 만들지만 픽셀 단위 정렬을 보장하지 않으므로 눈높이와 어깨 기준을 확인한 뒤 배치한다. 이 팩에는 눈깜빡임·걷기 애니메이션 프레임이 포함되지 않는다.

## 검수와 다음 개발

`node scripts/build-art-pack.mjs --verify-complete`는 계획된 파일 존재, PNG 형식·실제 크기·해시, 투명 요청 자산의 알파를 확인하고 목록과 갤러리를 갱신한다. 1챕터 핫스폿 좌표는 생성된 이미지에 맞춘 초기 측정값이다. 실제 게임에서 320·360 CSS px, 대화창 표시, 밝기 설정, 상태 교체를 검수한 뒤 확정한다.

웹 배포 때는 장별로 이미지를 지연 로드하고 현재 장면과 가까운 시점만 미리 읽는다. 원본 PNG 전체를 첫 화면에서 모두 로드하지 않는다. 배포본 최적화와 WebP 밀도별 내보내기는 실제 게임 빌드 단계에서 수행한다. 이후 UI 요청을 반영해 웹 실행·저장·1챕터 P01~P25가 구현됐다. [실행 UI 명세](../../../docs/07_UI_IMPLEMENTATION.md)와 [완성 UI 이미지 v02](../../ui-screens/v02/README.md)를 확인한다. 앱 패키징과 배포 자산 최적화는 후속 단계다.

## 최종 확인

113개 PNG와 63개 SVG가 존재하며 누락은 0개다. 투명 요청 PNG 50개는 실제 알파 채널을 확인했다. [전체 생성 기록](generation-log-final.json)은 각 파일의 생성·편집 출처를 기록한다. 이미지 생성은 내장 image_gen으로 수행했고 정확한 글자·아이콘은 별도 SVG로 작성했다. 모든 생성 프롬프트는 asset-plan-final.json에 보관한다.

현재 UI 전체 글꼴은 Pretendard Variable이다. 폰트 원본과 라이선스는 fonts/에 포함하며 SVG 단서는 앱에서 inline으로 렌더링해 같은 글꼴을 상속한다. 별도 편집기에서 SVG를 열면 프리텐다드 설치 여부를 확인한다.
